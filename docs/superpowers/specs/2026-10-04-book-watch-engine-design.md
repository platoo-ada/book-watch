# book-watch Engine — Design Spec

วันที่: 2026-10-04 · สถานะ: build เสร็จ แก้ให้ตรงกับของจริงแล้ว (ดูข้อ 14) · โปรเจกต์ย่อย 1 จาก 3

## 1. เป้าหมาย

เฝ้าตลาดหนังสือไทย (หนังสือไทยและหนังสือแปลไทย) รายสัปดาห์ เพื่อเป็นวัตถุดิบเขียนบทความ Whale and Vibe (WnV)

ทุกเช้าวันจันทร์ ระบบดึงรายการหนังสือขายดี แนะนำ และออกใหม่จากร้านและสำนักพิมพ์ไทย รวมเล่มเดียวกันจากหลายแหล่งเป็นรายการเดียว เรียงตามจำนวนแหล่งอิสระที่พูดถึง แล้วส่งออกเป็นไฟล์ในรีโปและข้อความ ntfy

สำเร็จเมื่อ: เช้าวันจันทร์ Platoo ได้ ntfy 4 บรรทัด เปิด `latest.md` แล้วเห็นว่าสัปดาห์นี้เล่มไหนเด่น มาจากแหล่งไหน และเล่มไหนเพิ่งโผล่ครั้งแรก โดยทุกรายการกดลิงก์ไปต้นทางได้

## 2. ขอบเขต

อยู่ในขอบเขต

- ดึงข้อมูลจาก 6 แหล่งไทย (ข้อ 4)
- รวมเล่มซ้ำ เรียง กรอง ด้วยกฎล้วน ไม่มี LLM
- ส่งออก `latest.md`, `latest.json`, ไฟล์รายสัปดาห์ และ ntfy

นอกขอบเขต (ทำภายหลังเป็นโปรเจกต์แยก)

- หน้า board บน Aquarium `/monitor/book-watch` (โปรเจกต์ย่อย 2)
- ต่อ `latest.json` เข้า skill `wnv-publish` (โปรเจกต์ย่อย 3)
- LLM ให้คะแนนหรือเสนอมุมบทความ
- แหล่งต่างประเทศ (NYT, Goodreads ฯลฯ)
- แหล่งที่กันบอต: นายอินทร์ (Cloudflare บล็อก) และ Kinokuniya TH (403) ไม่หาทางอ้อม
- MEB, Matichon, B2S, Ookbee: หน้าเปิดได้แต่ยังไม่ได้แกะโครง เติมทีละแหล่งหลังรอบแรกนิ่ง

## 3. โครงโดยรวม

รีโป `platoo-ada/book-watch` (public เหมือน watch-kb เพื่อให้ Aquarium ดึงไฟล์ raw ได้ในโปรเจกต์ย่อย 2) อยู่ที่ `~/Work-space/book-watch` ใช้ Python 3.12 stdlib ล้วน ไม่มี dependency

```
book-watch/
  run.py                  จุดเริ่ม: ดึง → รวม → เรียง → เขียนไฟล์
  bookwatch/
    fetch.py              get() + ตัวห่อ src() บันทึก ok/error ต่อแหล่ง
    sources.py            ฟังก์ชันแกะข้อมูล 1 ตัวต่อ 1 แหล่ง คืนรายการ Entry
    normalize.py          ทำความสะอาดชื่อ, ตรวจ ISBN, สร้าง key
    merge.py              รวม Entry เป็น Book, นับแหล่ง, เรียง, กรอง
    render.py             เขียน latest.md, latest.json, brief.txt
  tests/
    fixtures/             ข้อมูลจริงที่บันทึกจากแต่ละแหล่ง (ไม่ commit)
    test_fetch.py  test_render.py  test_run.py
    test_normalize.py
    test_merge.py
    test_sources.py       แกะ fixture แล้วได้ Entry ตามคาด
  tools/
    probe.py              เช็คว่าแต่ละแหล่งเข้าถึงได้
    record_fixtures.py    บันทึก fixture
  latest.md  latest.json  brief.txt (brief ไม่ commit)
  weekly/YYYY-Www.md  weekly/YYYY-Www.json
  .github/workflows/fetch.yml
  README.md
```

ขอบเขตของแต่ละส่วน

- `sources.py` รู้จักรูปร่างข้อมูลของแต่ละเว็บ และเป็นส่วนเดียวที่ต้องแก้เมื่อเว็บเปลี่ยนโครง ทุกฟังก์ชันรับข้อความดิบ (string) คืนรายการ Entry จึงทดสอบกับ fixture ได้โดยไม่ต่อเน็ต
- `normalize.py` และ `merge.py` ไม่รู้จักแหล่งใดเป็นพิเศษ ทำงานกับ Entry เท่านั้น
- `render.py` รับผลจาก `merge.py` อย่างเดียว

## 4. แหล่งข้อมูลรอบแรก

ทุกแหล่งยิงสัปดาห์ละครั้ง คำขอรวมต่อรอบไม่เกิน 10 ครั้ง

| id | แหล่ง | URL | รูปแบบ | รายการที่ได้ | ISBN |
|---|---|---|---|---|---|
| `seed` | SE-ED (API) | `https://mp-api.se-ed.com/web-bff/homepage-layout` (ส่ง header `Origin` และ `Referer` เป็น `https://www.se-ed.com`) | JSON | ขายดี, แนะนำ, ออกใหม่, pre-order | `variants[0].sku` |
| `seed` | SE-ED (หน้าจัดอันดับ) | `https://m2.se-ed.com/product/bestseller/1` | HTML | ขายดีรายวัน | มีในหน้า |
| `chula` | ศูนย์หนังสือจุฬาฯ | `https://www.chulabook.com/` (JSON ใน `__NEXT_DATA__`) | JSON ฝังใน HTML | ขายดี, ออกใหม่, แนะนำ, pre-order | `barcode` |
| `amarin` | Amarin | `https://amarinbooks.com/wp-json/wc/store/v1/products?orderby={popularity,date}&order=desc&per_page=20` | JSON | ยอดนิยม, ออกใหม่ | ไม่มี (รหัสภายใน) |
| `salmon` | Salmon | `https://salmonbooks.net/wp-json/wc/store/v1/products?orderby={popularity,date}&order=desc&per_page=20` | JSON | ยอดนิยม, ออกใหม่ | `sku` เป็นส่วนใหญ่ |
| `the101` | The 101 | `https://www.the101.world/feed/` | RSS | บทความ | ไม่มี |
| `aday` | a day | `https://adaymagazine.com/feed/` | RSS | บทความ | ไม่มี |

SE-ED สองรายการใช้ id เดียวกัน (`seed`) เพราะเป็นเจ้าเดียวกัน นับเป็นแหล่งอิสระ 1 แหล่ง

การจับคู่ชื่อ section ของ SE-ED กับประเภทรายการ ทำด้วยคำในชื่อ section ไม่ใช้ตำแหน่ง เพราะร้านสลับลำดับได้

| คำในชื่อ section | ประเภท |
|---|---|
| "ขายดี" | `bestseller` |
| "แนะนำ" | `recommended` |
| "ออกใหม่" | `new` |
| "PRE-ORDER" หรือ "สั่งจอง" | `preorder` |

section ที่ชื่อไม่ตรงคำใดเลยให้ข้าม ถ้าชื่อตรงมากกว่าหนึ่งคำ ใช้คำแรกตามลำดับในตารางนี้ ส่วน section อย่าง "สินค้าไลฟ์สไตล์แนะนำ" จะเข้าประเภท `recommended` แต่สินค้าข้างในถูกตัดด้วยกฎกรอง `not_book` ในข้อ 7

## 5. โครงข้อมูล

Entry คือ 1 แถวที่แหล่งหนึ่งรายงาน

```
Entry: source, list, rank, title_raw, author, translator, isbn, category,
       lang, is_book, label, url, cover
```

- `is_book` ตั้งโดยตัวแกะของแต่ละแหล่ง เพราะแต่ละร้านบอกว่าอะไรไม่ใช่หนังสือด้วยวิธีต่างกัน
- `lang` และ `translator` มีเฉพาะแหล่งที่ให้มา (ตอนนี้คือจุฬาฯ)

- `list` เป็นหนึ่งใน `bestseller | recommended | new | preorder`
- `rank` คือลำดับในรายการของแหล่งนั้น เริ่มที่ 1
- ช่องที่แหล่งไม่ให้มาเป็น `null` ไม่เดาเติม

`latest.json` (`schema_version: 1`) เป็นสัญญากับโปรเจกต์ย่อย 2 และ 3

```json
{
  "schema_version": 1,
  "generated_at": "2026-10-05T08:31+07:00",
  "week": "2026-W41",
  "sources": [
    {"id": "seed", "name": "SE-ED", "url": "...", "ok": true, "error": null,
     "fetched_at": "2026-10-05T08:31+07:00", "count": 62}
  ],
  "books": [
    {
      "key": "isbn:9786164810600",
      "isbn": "9786164810600",
      "title": "ทุกอย่างที่เธอเป็น...ดีเสมอ",
      "author": null,
      "category": "อารมณ์ จิตใจ ความรู้สึกต่าง ๆ",
      "maybe_translated": false,
      "translator": null,
      "article_sources": [],
      "source_count": 2,
      "list_types": ["bestseller", "recommended"],
      "featured": true,
      "excluded_reason": null,
      "first_seen": "2026-W41",
      "mentions": [
        {"source": "seed", "list": "recommended", "rank": 1,
         "label": "สินค้าแนะนำประจำสัปดาห์",
         "title_raw": "...", "url": "...", "cover": "..."}
      ]
    }
  ],
  "articles": [
    {"source": "the101", "title": "...", "url": "...",
     "published": "ตามที่ feed ให้มา", "matched_keys": ["isbn:978..."]}
  ]
}
```

`sources` มี 1 แถวต่อ 1 คำขอ (feed) แหล่งที่ยิงสองคำขอจึงมีสองแถวที่ `id` เดียวกัน เช่น "SE-ED (API)" กับ "SE-ED (จัดอันดับ)" ตัวเลข "ดึงได้ x จาก y" นับเป็นคำขอ ส่วน `source_count` ของเล่มนับตาม `id`

เวลาที่มาจากแหล่ง (`published`) เก็บเป็นข้อความตามที่แหล่งให้ ไม่แปลงเขตเวลา ตามกฎ As-Published ของ watch-kb ส่วน `generated_at` และ `fetched_at` ระบุ `+07:00` ชัดเจน

## 6. การรวมเล่มซ้ำ

Entry สองแถวถือเป็นเล่มเดียวกันเมื่อ ISBN-13 ตรงกัน หรือชื่อที่ทำความสะอาดแล้วตรงกันทุกตัวอักษร ความสัมพันธ์นี้ส่งต่อกันได้ (A ตรง B ด้วย ISBN, B ตรง C ด้วยชื่อ ทั้งสามเป็นเล่มเดียว) เหตุผลที่ไม่ใช้ ISBN อย่างเดียว: ฉบับปกแข็งกับปกอ่อนมี ISBN ต่างกันแต่เป็นงานเดียวกัน และบางแหล่งไม่มี ISBN

ISBN-13 ที่ถูกต้องคือ 13 หลัก ขึ้นต้น 978 หรือ 979 และ check digit ผ่าน

`key` ของ Book คือ `isbn:<ISBN ที่น้อยที่สุดในกลุ่ม>` ถ้ากลุ่มมี ISBN ไม่มีก็ใช้ `title:<ชื่อที่ทำความสะอาดแล้ว>`

การทำความสะอาดชื่อ (ใช้ทั้งสร้าง key และแสดงผล)

- ตัดคำนำหน้าในวงเล็บเหลี่ยม เช่น `[ตาก]` และคำนำหน้า `PREORDER` หรือ `PRE-ORDER` (ไม่สนตัวพิมพ์เล็กใหญ่)
- ตัดวงเล็บท้ายชื่อที่เป็นป้ายของร้าน (ตัดซ้ำจนไม่เหลือ) วงเล็บอื่นคงไว้ เช่น `(การปกครอง)` วงเล็บถือเป็นป้ายเมื่อเข้าข้อใดข้อหนึ่ง
  - มีคำใดคำหนึ่งอยู่ข้างใน: ปกแข็ง, ปกอ่อน, ปกใหม่, จอง, รอบปกติ, รอบพิเศษ, พิมพ์ครั้งที่, ฉบับปรับปรุง
  - ขึ้นต้นด้วย พร้อม หรือ ราคาปก เช่น `(พร้อมโปสการ์ดลายเซ็นนักเขียน)`, `(ราคาปก 295.-)`
  - ข้างในเป็นคำนี้พอดีทั้งวงเล็บ: `New`, `re-newed`, `อ่อน`, `แข็ง`
- ตัดส่วนท้ายแบบขีดตามด้วยชนิดปก: `– ปกแข็ง`, `– ปกอ่อน`
- ยุบช่องว่างซ้ำ ตัดช่องว่างหัวท้าย
- สำหรับ key เท่านั้น: แปลงตัวอังกฤษเป็นตัวเล็ก ตัดเครื่องหมายวรรคตอนและช่องว่างทั้งหมด

ป้ายที่ยังไม่ตัด เพราะไม่มีรูปแบบที่แยกจากชื่อจริงได้ชัด: "พิมพ์ 34" นอกวงเล็บ, `“New Edition”`, `+MP3`, `(Book Set : 2 เล่ม)`, `(บรรจุกล่อง)`

การรวม

- ในเล่มเดียวกัน ถ้าแหล่งเดียวกันรายงานประเภทรายการเดียวกันซ้ำ เก็บแถวที่อันดับดีที่สุดแถวเดียว
- ไม่ใช้การเทียบชื่อแบบคล้ายกัน (fuzzy) ในรอบแรก ยอมให้เล่มเดียวกันแยกเป็นสองรายการดีกว่ารวมผิดเล่ม

`maybe_translated` จริงเมื่อแหล่งระบุชื่อผู้แปล หรือเมื่อชื่อขึ้นต้นด้วยคำอักษรละตินอย่างน้อย 2 คำแล้วตามด้วยอักษรไทย (กรณีหลังเป็นการเดา) ในผลลัพธ์แสดงเป็น "อาจเป็นงานแปล" ไม่ยืนยัน

`first_seen` คือสัปดาห์แรกสุดที่เคยเห็นเล่มนี้ ได้จากการอ่าน `weekly/*.json` ทุกไฟล์และ `latest.json`: key ที่เคยมีได้สัปดาห์ที่เก่าที่สุดในประวัติ key ใหม่ได้สัปดาห์ปัจจุบัน ไฟล์ที่ไม่มีหรืออ่านไม่ได้ให้ข้าม ถ้าไม่มีประวัติเลย ทุกเล่มได้สัปดาห์ปัจจุบัน

เหตุผลที่ไม่อ่านแค่ไฟล์สัปดาห์ก่อน: เล่มที่หายไปหนึ่งสัปดาห์ (เช่น แหล่งนั้นดึงไม่ได้) จะกลับมาเป็น "ใหม่สัปดาห์นี้" ทั้งที่ไม่ใช่ ผลที่ตามมาคือเล่มที่หายไปนานแล้วกลับมาก็ไม่นับว่าใหม่ และห้ามลบไฟล์เก่าใน `weekly/`

การจับคู่กับประวัติใช้ key ของเล่ม และ key แบบ `title:` ของชื่อที่แสดง เพื่อให้เล่มที่ key เปลี่ยนจาก `title:` เป็น `isbn:` ยังได้ค่าเดิม

## 7. การกรองและการเรียง

การกรองไม่ลบข้อมูล เล่มที่ไม่ผ่านยังอยู่ใน `latest.json` โดย `featured: false` และมี `excluded_reason`

| `excluded_reason` | เงื่อนไข |
|---|---|
| `not_book` | ทุกแหล่งที่รายงานเล่มนี้บอกว่าไม่ใช่หนังสือ: หมวด SE-ED ที่ `id` ไม่ขึ้นต้นด้วย `book`, รหัสในหน้าจัดอันดับ SE-ED ที่ไม่ใช่ ISBN, หมวด WooCommerce ที่มีคำ ของแถม พรีเมี่ยม หรือ SALMART, รายการจุฬาฯ ที่ `type` ไม่ใช่ `book` (รายการ e-voucher ของ SE-ED ข้ามตั้งแต่ตอนแกะ) |
| `not_thai` | แหล่งระบุภาษา และไม่มีแหล่งใดระบุว่าเป็นภาษาไทย (เช่น หนังสือต่างประเทศของจุฬาฯ) |
| `exam_reference` | ชื่อหรือหมวดมีคำ: คู่มือสอบ, เตรียมสอบ, ติวเข้ม, ข้อสอบ, แบบทดสอบ, แบบฝึกหัด, แบบเรียน, พจนานุกรม, TGAT, TPAT, A-LEVEL, MOCK TEST, TOPIK, อนุบาล, ประถม, มัธยม, ม.ต้น, ม.ปลาย, ป.1 ถึง ป.6, ม.1 ถึง ม.6 หรือหมวดของแหล่งเป็น `test-prep` หรือ `medical-and-nursing` (หมวดตำราแพทย์และพยาบาลของจุฬาฯ) |

ตรวจตามลำดับในตาราง ใช้เหตุผลแรกที่ตรง

รายการคำอยู่ในค่าคงที่ต้นไฟล์ `merge.py` แก้ได้โดยไม่แตะตรรกะ

`exam_reference` จึงครอบคลุมทั้งคู่มือสอบ แบบเรียน พจนานุกรม และตำราคลินิก ตำรามหาวิทยาลัยหมวดอื่นของจุฬาฯ (บัญชี ศึกษาศาสตร์ ฯลฯ) และหนังสือเรียนภาษา ไม่ถูกกรอง เพราะอยู่หมวดเดียวกับหนังสือทั่วไป

การเรียงเล่มที่ `featured: true` จากมากไปน้อย (ลำดับใน `latest.json` และหมวด "เล่มเด่น")

1. `source_count` จำนวน id แหล่งที่ไม่ซ้ำกันที่มีเล่มนี้
2. จำนวน `list_types`
3. อันดับดีที่สุดในรายการ `bestseller` (ไม่มีถือว่าท้ายสุด)

## 8. ผลลัพธ์

`latest.md` (ภาษาไทย)

1. หัว: สัปดาห์ เวลาที่สร้าง จำนวนแหล่งที่ดึงได้จากทั้งหมด
2. **เล่มเด่นของสัปดาห์**: เล่มที่ `source_count` อย่างน้อย 2 สูงสุด 15 เล่ม แต่ละเล่มมีชื่อ ผู้แต่ง (ถ้ามี) ป้ายรายการที่ติดพร้อมลิงก์ต้นทางทุกแหล่ง และป้าย "ใหม่สัปดาห์นี้" ถ้า `first_seen` เป็นสัปดาห์ปัจจุบัน
3. **อันดับที่ร้านประกาศ**: รายการ `bestseller` แยกตามแหล่ง แหล่งละไม่เกิน 10 เล่ม เรียงตามอันดับ ใช้คำว่า "อันดับที่ร้านประกาศ" ไม่ใช้ "ยอดขาย" เพราะบางร้านเป็นรายการที่แอดมินเลือก แต่ละบรรทัดเป็น bullet (`- `) ไม่ใช้เลขนำหน้า เพราะ Markdown เรียงเลขใหม่เองและจะกลบช่องว่างของเล่มที่ถูกกรอง อันดับจริงอยู่ในข้อความลิงก์ เช่น `SE-ED ขายดี #2`
4. **ออกใหม่และสั่งจอง**: รวมทุกแหล่ง ไม่เกิน 20 เล่ม เรียงตามอันดับของร้าน (ข้อ 7)
5. **แนะนำ**: รวมทุกแหล่ง ไม่เกิน 15 เล่ม เรียงตามอันดับของร้าน (ข้อ 7)
6. **บทความเกี่ยวกับหนังสือ**: ไม่เกิน 10 รายการ
7. **ดึงไม่ได้**: แหล่งที่ล้มเหลวพร้อมข้อความ error ถ้าไม่มีให้เขียนว่า "ดึงได้ครบทุกแหล่ง"

ถ้าหมวดใดไม่มีข้อมูล เขียนว่า "ไม่มีข้อมูลสัปดาห์นี้" ไม่เว้นว่าง

`weekly/YYYY-Www.md` และ `.json` เป็นสำเนาของ latest ณ วันที่รัน ใช้เลขสัปดาห์ ISO ตามเวลาไทย รันซ้ำในสัปดาห์เดียวกันเขียนทับไฟล์เดิม

`brief.txt` สำหรับ ntfy 4 บรรทัด

```
เล่มเด่น: <ชื่อ 1> (<n> แหล่ง), <ชื่อ 2>, <ชื่อ 3>
ใหม่สัปดาห์นี้: <จำนวน> เล่ม เช่น <ชื่อ>
ขายดี SE-ED อันดับ <n>: <ชื่อ>
แหล่ง: <ok>/<ทั้งหมด> · <ลิงก์ latest.md>
```

บรรทัดที่ 3 คือเล่มที่อันดับดีที่สุดของ SE-ED ในบรรดาเล่มที่ `featured: true` และ `<n>` คืออันดับจริงที่ร้านประกาศ ไม่ใช่ 1 เสมอ เพราะอันดับ 1 ของร้านอาจเป็นของที่ถูกกรอง (รอบแรกอันดับ 1 เป็นคู่มือ TGAT และสมุดระบายสี) ถ้าไม่มีเล่มใดเลยเขียนว่า "ขายดี SE-ED: ไม่มีข้อมูล" บรรทัดแรกเมื่อไม่มีเล่มติด 2 แหล่งเขียนว่า "เล่มเด่น: ไม่มีเล่มที่ติด 2 แหล่งขึ้นไป"

## 9. การรัน

GitHub Actions `.github/workflows/fetch.yml` โครงเดียวกับ watch-kb

- cron `30 1 * * 1` (จันทร์ 08:30 เวลาไทย) และ `workflow_dispatch`
- ขั้นตอน: checkout, setup-python 3.12, `python3 -m unittest`, `python3 run.py`, commit `latest.*` กับ `weekly/`, ส่ง ntfy
- secret `NTFY_TOPIC` ตั้งในรีโป ไม่อยู่ในโค้ด
- ntfy: มี `brief.txt` ส่งระดับปกติ ไม่มีส่ง "book-watch: fetch ล้มเหลว" ระดับสูง

GitHub Actions schedule ไม่รับประกันเวลา (watch-kb เคยช้า 5 ชั่วโมง) รับได้สำหรับงานรายสัปดาห์

User-Agent ใช้แบบระบุตัว `book-watch/1.0 (+https://github.com/platoo-ada/book-watch)` เป็นค่าตั้งต้น ถ้าแหล่งใดปฏิเสธ UA นี้แต่รับ UA ของเบราว์เซอร์ ให้บันทึกใน README ว่าแหล่งนั้นใช้ UA เบราว์เซอร์

## 10. การจัดการข้อผิดพลาด

- แต่ละแหล่งห่อด้วย `src()` แยกกัน แหล่งหนึ่งพังไม่กระทบแหล่งอื่น timeout 40 วินาทีต่อคำขอ ไม่ retry ในรอบเดียวกัน
- แหล่งที่ตอบกลับได้แต่แกะแล้วได้ 0 รายการ ถือว่าล้มเหลว (`error: "parsed 0 items"`) เพื่อจับกรณีเว็บเปลี่ยนโครง
- ดึงได้อย่างน้อย 1 แหล่ง: เขียนผลลัพธ์ตามปกติ และระบุแหล่งที่พังในหมวด "ดึงไม่ได้"
- ดึงไม่ได้ทุกแหล่ง: ไม่เขียน `latest.*` และ `brief.txt`, `run.py` ออกด้วยรหัส 1, workflow ส่ง ntfy แจ้งล้มเหลว ไฟล์สัปดาห์ก่อนคงอยู่
- ไม่มีค่าประมาณการหรือค่าเติมเอง ช่องที่ไม่มีข้อมูลเป็น `null`

## 13. ความเสี่ยงและข้อจำกัดที่ยอมรับ

- **น้ำหนักเอียง**: ร้านที่ขายหลายสำนักพิมพ์มีแค่ SE-ED กับจุฬาฯ และจุฬาฯ หนักตำรา เล่มที่ติดสองแหล่งขึ้นไปอาจมีน้อยในบางสัปดาห์ หมวด "เล่มเด่น" จึงอาจสั้น แก้ด้วยการเติมแหล่งภายหลัง ไม่ลดเกณฑ์
- **ร้านสำนักพิมพ์เชียร์ของตัวเอง**: Amarin และ Salmon แสดงเฉพาะหนังสือตัวเอง นับเป็นแหล่งได้ แต่ผู้อ่านผลลัพธ์เห็นชื่อแหล่งทุกครั้งจึงตัดสินเองได้
- **"ขายดี" ไม่ใช่ยอดขายจริง**: บางรายการแอดมินเลือกเอง ผลลัพธ์จึงใช้คำว่า "อันดับที่ร้านประกาศ"
- **งานแปลเดาจากชื่อ**: ไม่แม่น แสดงเป็น "อาจเป็นงานแปล"
- **เว็บเปลี่ยนโครง**: แหล่งที่แกะได้ 0 รายการขึ้นหมวด "ดึงไม่ได้" ทันที แก้ที่ `sources.py` จุดเดียว
- **ข้อมูลสาธารณะ**: รีโปเป็น public เก็บเฉพาะชื่อ ผู้แต่ง ISBN หมวด ลิงก์ และ URL ปก (ไม่ดาวน์โหลดรูป) ไม่มีข้อมูลงานของ Platoo
- **SE-ED มีรายการขายดี 3 ชุด**: ขายดีประจำวันในหน้าแรก หน้าจัดอันดับรายวัน และขายดีของสำนักพิมพ์ซีเอ็ด ทั้งสามเข้าประเภท `bestseller` เลขอันดับของ SE-ED จึงซ้ำกันได้
- **ตัดป้ายท้ายชื่อเกิน**: ชื่อจริงที่ลงท้ายด้วยวงเล็บแบบป้าย เช่น "ชีวิต (พร้อมจะรัก)" หรือ "คนดี (ที่จองหอง)" จะถูกตัดวงเล็บ ยอมรับเพราะในข้อมูลจริงทุกกรณีที่ตัดเป็นป้ายของร้าน
